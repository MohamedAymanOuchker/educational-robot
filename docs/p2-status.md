# P2 finalization status

Development revision: 8 October 2026. This update addresses the original audit's P2 findings 10 (saving/progress), 11 (current feature scope), the app scan/display lifecycle in 12, and the operating-guide portion of 15. It does not close the physical-build, CAD-export or research-record requirements in [P1 status](p1-status.md).

## Completed: local programs and truthful practice progress

- **Save/Open:** the Code screen now stores named programs on the device, including lesson, save time, block parameters, positions, colors and nested children. Opening creates independent editable blocks with rebuilt parent links. A new name keeps a separate copy; replacement uses case-insensitive names and asks for confirmation.
- **Workspace protection:** Open asks before replacing unsaved changes, Clear asks before removing blocks, and switching tabs retains the workspace. Saved programs remain available after clearing or recreating the editor. Closing the app still requires an explicit Save; autosave, file export and cloud backup are not implemented.
- **Storage failures:** failed writes do not show a successful Save or award practice progress. Unsupported or malformed stored data is reported and retained rather than silently reset. Concurrent program saves are serialized. The library is limited to 50 programs of at most 100 blocks each, with names of 1–64 characters.
- **Practice checks:** Save no longer awards lesson completion. The executor records the actions actually completed during a successful run; skipped branches, zero-valued movement/waits, failures, cancellation and an unconfirmed final STOP do not qualify. Sensor lessons require an executed response inside a true condition. See the [user manual](user-manual.md#practice-levels) for all five requirements.
- **Accurate progress:** the progress bar now starts at 0% and reaches exactly 100% for five checks. Completion refers to the lesson captured when the run starts. The editor does not advance itself during completion; the next lesson is selected on Home. Existing lesson access is preserved during migration, while old presence-only badges do not count as executed practice.
- **Live connection status:** connection flags are no longer persisted or restored from disk. The home page cancels its connection subscription when disposed. Removed the unused competing `ProgressService` so the app has one progress store.

Practice checks establish that the app observed successful command completion. They do not measure actual wheel displacement, path accuracy, obstacle clearance or student learning. The teacher's assessment and physical acceptance tests remain necessary.

## Completed: feature scope, discovery and telemetry display

- **Four useful tabs:** Home, Connect, Code and Sensors. Robot Execution opens from Run in Code; the empty Run tab was removed. The connection screen offers Bluetooth only. Wi-Fi scanning, password entry, connection stubs, the unused `wifi_iot` dependency and Wi-Fi permissions were removed. The Android manifest now declares BLE as required.
- **Owned scan lifecycle:** discovery filters on the advertised robot service UUID, reports permission/adapter errors instead of returning a misleading empty result, and ends after a bounded scan. Native results, timers and subscriptions are cleaned up on completion/cancellation. Cancelling during permission work prevents a late scan from starting; cancelling pending native startup waits for startup then requests stop. These paths are simulated in tests; phone permission behavior and radio timing remain physical-device checks.
- **One lesson definition:** the editor uses typed `BlockType` lists rather than historical Blockly XML. Home and Code share the names and descriptions. Only movement/Stop, Wait, If Distance and Auto Navigate appear, at their respective levels; there are no unused loop, Else, math or path-planning definitions in the active toolbox.
- **Honest sensor display:** readings arrive automatically without pretend monitoring Start/Stop buttons. No sample, a missing/invalid field, disconnect or stale telemetry shows Unavailable. New telemetry replaces the prior packet rather than refreshing old optional fields. Distance includes firmware age and reception age; display expiry is checked every 250 ms against a 500 ms limit. The dashboard no longer labels a single front reading as “All Clear.” Battery, chip temperature and relative heading are described with their actual limitations.
- **Current guides:** the [manual](user-manual.md) and [curriculum](curriculum-guide.md) describe the implemented five-level sequence and distinguish single distance checks, normal Stop blocks, whole-run Stop, and bounded autonomy. Earlier versions are preserved under [docs/archive](archive/) with rebased links and a historical-status notice. Original reported research figures were retained there and remain subject to reconciliation. The README no longer claims implemented Arabic localization.

## Storage and migration

`ProgramStore` uses the `savedPrograms.v1` SharedPreferences key containing a JSON object with `version: 1` and a `programs` list. Each entry contains `name`, `level`, `savedAt` (UTC) and `blocks`. Block types use stable enum names, parameters use their documented units, and children retain their array order. Parent references are reconstructed rather than serialized. Unknown block types, invalid parameters/positions, leaf children, duplicate names and excessive block counts are rejected.

`AppState` uses `practiceProgress.v1` with `version`, `currentLevel`, `completedLevels` and `legacyUnlockedThrough`. Old `currentLevel` and `completedLevels` preferences are read only to preserve lesson access and are retained. Old `robotConnected` values are ignored. The new format is written on a successful state change; malformed or newer-version state is not overwritten.

This is local app storage, not a backup system. Uninstalling the app or clearing its data removes the library and progress. Recovery/import/export tooling is outside this update.
